# AAA — Telegram-бот для актов строительных работ

Бот помогает готовить акты скрытых работ: ведёт объект, позиции, материалы,
сертификаты и циклы типовых работ, заполняет шаблон `shablonact.docx` и
отправляет готовый файл в Telegram.

## Возможности

- пошаговое создание акта: объект → позиция → работа → чертёж → материалы → даты;
- циклы работ для серии однотипных актов;
- справочники материалов, категорий и сертификатов;
- готовые акты, история печати, недоделанные черновики и архив;
- редактирование и пересборка акта;
- поиск по номеру, позиции, дате/месяцу, работе и материалам;
- экспорт реестра в CSV и Excel, пакетная сборка актов в один `.docx`;
- массовое переименование файлов и архивирование за период;
- удаление с подтверждением: файл переносится в `acts/_deleted/`;
- читаемые имена файлов: `АКТ №103 Бетонирование поз. №33.docx`;
- уникальность номера акта в пределах объекта на уровне БД;
- атомарное сохранение: файл и запись БД не расходятся;
- автоматические резервные копии БД и файлов;
- активный черновик FSM хранится в SQLite и переживает перезапуск;
- белый список пользователей и администраторы.

## Быстрый старт

Требуется Python 3.11+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

Copy-Item .env.example .env
notepad .env          # вставьте BOT_TOKEN
python bot.py
```

При первом запуске отправьте боту `/myid` — он покажет ваш Telegram ID даже
при закрытом доступе. Добавьте ID в `.env`:

```env
ADMIN_IDS=ваш_id
```

и перезапустите бота. Без заполненного белого списка доступ закрыт. Для
временного открытого режима можно поставить `ALLOW_ANY_USER=1`, но для
продакшена лучше этого не делать.

## Управление ботом

```powershell
.\start_bot.ps1    # запустить watchdog, он поднимет бота
.\stop_bot.ps1     # остановить watchdog и бота
.\status_bot.ps1   # показать статус и хвост лога
```

Если PowerShell не разрешает скрипты, используйте `.bat`-файлы
(`start_bot.bat`, `stop_bot.bat`, `status_bot.bat`) или запускайте так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start_bot.ps1
```

`watchdog_bot.ps1` проверяет бота каждые 5 секунд и поднимает его после
падения. Бот раз в минуту обновляет маленький файл `.bot.heartbeat`; если
heartbeat не менялся 10 минут, watchdog перезапускает зависший процесс.
Это одна короткая запись в минуту — нагрузка на диск незаметна.
PID хранятся в `.bot.pid` и `.watchdog.pid`, логи — в
`logs/bot.out.log`, `logs/bot.err.log` и `logs/watchdog.log`. Повторный
запуск не создаёт второй экземпляр. При остановке watchdog завершается
первым, иначе он снова поднял бы бота.

`stop_bot.ps1` создаёт файл `.bot.disabled`: после команды «выключи» бот
не поднимется и при следующем входе в Windows. `start_bot.ps1` удаляет
этот файл и снова разрешает автозапуск. Если нужно убрать автозапуск
совсем, используйте `remove_autostart.ps1`.

## Автозапуск при входе в Windows

```powershell
.\install_autostart.ps1   # задача планировщика AAA-Bot-Watchdog
.\remove_autostart.ps1    # убрать автозапуск
```

Задача запускает watchdog при входе пользователя в Windows, а watchdog —
бота. Это надёжнее, чем пытаться ловить запуск Telegram: вход в Telegram
не является системным событием. Если задача планировщика недоступна,
`install_autostart.ps1` создаст ярлык в папке автозагрузки.

Автозапуск срабатывает только после входа в Windows. Если компьютер спал,
после пробуждения уже запущенный бот обычно продолжает работу; если процесс
был завершён — watchdog поднимет его в течение нескольких секунд.

## Нагрузка

В простое бот и watchdog занимают около 250–300 МБ оперативной памяти и
почти не нагружают CPU: бот раз в несколько секунд делает короткий запрос
к Telegram, остальное время ждёт. Основная память приходится на Python и
aiogram, watchdog добавляет около 80 МБ. Это заметно меньше, чем браузер
или Telegram Desktop. Логи бота автоматически ротируются при перезапуске
после достижения 5 МБ.

## Настройка

Все пути считаются от каталога проекта (`config.py`), запускать можно из любой
директории. Значения по умолчанию:

| Путь | Назначение |
| --- | --- |
| `acts.db` | база данных SQLite |
| `shablonact.docx` | шаблон акта |
| `project/` | исходные PDF-чертежи (не коммитятся) |
| `acts/` | готовые акты (не коммитятся) |
| `acts/_deleted/` | архив удалённых файлов |
| `acts/_old/` | старые версии файлов после редактирования |
| `acts/_archive/` | акты, выведенные в архив по дате |
| `acts/_packages/` | собранные пакеты для печати |
| `backups/` | автобэкапы БД и файлов (хранится 30 копий) |
| `exports/` | CSV- и Excel-выгрузки реестра |
| `certificates/` | будущие сканы паспортов/сертификатов |

Переопределяются в `.env`: `DB_PATH`, `PROJECT_DIR`, `ACTS_DIR`,
`TEMPLATE_PATH`, `BACKUPS_DIR`, `EXPORTS_DIR`, `CERTIFICATES_DIR`,
`MAX_TELEGRAM_SIZE_MB`, `BACKUP_RETENTION`, `HEARTBEAT_INTERVAL_SECONDS`.

## Первичное заполнение

```powershell
python seed_object_only.py          # объект-пример и типы работ
python seed_material_categories.py  # категории материалов
python seed_materials.py            # типовые материалы
python seed_cycles.py               # готовые циклы работ
python sync.py                      # сканирование project/ и привязка PDF
```

Порядок важен: категории → материалы, объект → циклы и `sync.py`.

## Структура

- `bot.py` — запуск, доступ по белому списку, логирование, фоновые задачи;
- `config.py` — токен, пути, `ADMIN_IDS`, `ALLOWED_USER_IDS`;
- `db.py` — схема и запросы SQLite, безопасные миграции, уникальность номеров;
- `act_service.py` — атомарное сохранение акта и проверка комплектности;
- `registry_service.py` — поиск, CSV/Excel, пакетная печать, переименование, архив;
- `backup.py`, `heartbeat.py`, `fsm_storage.py` — надёжность и устойчивость;
- `handlers*.py` — сценарии Telegram;
- `keyboards.py`, `states.py`, `utils.py` — интерфейс и вспомогательная логика;
- `generate_act.py` — заполнение шаблона `.docx`;
- `storage.py` — архивы удалённых/старых/архивных файлов;
- `tools/` — служебные проверки (`check_db.py`, `check_materials.py`).

- не публикуйте токен и не пересылайте `.env`;

## Надёжность и резервные копии

При старте бот делает копию `acts.db` через SQLite backup API и ZIP с
текущими файлами `acts/` и `certificates/`. Затем копия повторяется каждый
день в 03:00. Хранятся последние 30 копий каждого типа (`BACKUP_RETENTION`).
Служебные архивы `_deleted`, `_old`, `_archive`, `_packages` в файловый
бэкап не попадают.

Акт сохраняется так: `.docx` собирается во временный файл → ставится на
место целевого → записывается строка в БД. Если запись не удалась, новый
файл удаляется, а прежняя версия восстанавливается. Номер готового акта
защищён частичным уникальным индексом SQLite; черновики в индекс не входят,
поэтому черновик можно спокойно подтвердить или удалить.

Перед финальным сохранением бот проверяет даты, позицию, материалы и
сертификаты, а также ищет полностью совпадающий готовый акт. Предупреждение
о дубле показывается в самом конце с номером существующего акта; сохранение
можно подтвердить осознанно.

## Поиск, экспорт и пакеты

В «📄 Мои акты» доступны:
- поиск по номеру, позиции, месяцу/дате, работе и материалам;
- экспорт реестра в CSV (разделитель `;`, UTF-8 BOM) или Excel `.xlsx`
  с фильтром и закреплённой шапкой;
- сборка всех готовых/распечатанных актов в один `.docx`;
- массовое переименование файлов под текущий формат;
- архивирование актов до указанной даты или за выбранный период
  (файлы → `acts/_archive/`, записи остаются в БД).

Для пакетной сборки используется `docxcompose`; при сборке между актами
вставляется разрыв страницы. Excel-выгрузка использует `openpyxl`.
